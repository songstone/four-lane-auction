### 0.3 완료 정의

AGENTS.md의 정의를 그대로 쓴다.

- 테스트와 빌드가 통과한다: `cd backend && ./gradlew test`, `cd frontend && npm run typecheck && npm run build`.
- 수용 기준을 항목별로 확인하고 결과를 보고한다.
- 사용자가 직접 확인할 방법(검증 방법의 curl·화면 절차)을 보고한다.
- 동시성 기능은 멀티스레드 테스트(`ExecutorService` + `CountDownLatch`) 없이 완료로 보지 않는다 (backend/AGENTS.md).
- 결정한 것은 `docs/PROGRESS.md`나 `docs/adr/`에 남긴다. 두 곳은 아직 없으므로 M0-01에서 만든다.
- 금지: 테스트를 지우거나 `@Disabled`·skip으로 통과시키기, 가짜 데이터나 하드코딩으로 완성한 것처럼 처리하기, 비밀값 커밋, 직접 측정하지 않은 성능 수치를 문서에 쓰기. 결제의 가짜 구현(`PaymentGateway`)은 PRD 5장이 정한 범위이므로 여기에 해당하지 않는다.

### 0.4 하위 단계: `[BE] → [GEN] → [FE] → [통합]`

| 단계 | 하는 일 | 끝나는 조건 |
|---|---|---|
| `[BE]` | 요청·응답 DTO(record), 컨트롤러, 서비스, 백엔드 테스트(`@WebMvcTest`, Testcontainers MySQL) | `./gradlew test` 통과, curl 확인 |
| `[GEN]` | 백엔드를 띄우고 `cd frontend && npm run gen-api`. 레인 이벤트나 개인 알림이 바뀌면 `docs/EVENTS.md`, 백엔드 이벤트 클래스, `frontend/src/realtime/events.ts`를 같은 커밋에서 맞춘다 | 생성 코드 커밋, `npm run typecheck`가 깨지는 곳 확인 |
| `[FE]` | 생성된 클라이언트와 TanStack Query로 화면을 만든다. 로딩·빈 상태·에러 상태를 모두 처리한다. 에러 문구는 `src/api/errorMessages.ts` 한 곳에 둔다 | `npm run typecheck`, `npm run build` |
| `[통합]` | 백엔드와 프론트를 함께 띄워 검증 방법의 화면 절차를 끝까지 해 본다 | 완료 보고 |

- 계약(API.md·EVENTS.md)과 다르게 만들어야 하면 멈추고 계약부터 고친다 (AGENTS.md "계약 변경 순서").
- REST 변경이 없는 작업에는 `[GEN]`이 없다. 이벤트만 바뀌면 `[GEN]` 자리에서 EVENTS.md와 `events.ts`를 맞춘다.

### 0.5 검증 명령의 공통 준비

```bash
API=http://localhost:8080          # 앱 포트. 관리 포트(actuator)는 M0-01에서 정한다
MGMT=http://localhost:8081
# 로그인해서 Access Token을 변수에 넣는다 (jq 필요). Refresh Token 쿠키는 cookies.txt에 남는다
USER1=$(curl -s -c cookies.txt -X POST $API/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"<시드 계정>","password":"<로컬 설정의 비밀번호>"}' | jq -r .accessToken)
```

- 계정은 M1-10의 시드 스크립트가 만든다. 비밀번호는 저장소에 커밋하지 않는 로컬 설정에서 읽는다.
- 아래 curl 예시의 ID(`12`, `345` 등)는 자리 표시 값이다. 시드 결과의 ID로 바꿔 쓴다.

**목표**: 빈 저장소에서 "화면 → REST → DB"와 "화면 ↔ WebSocket"이 한 번 이어지고, push하면 CI가 돌고, 첫 배포 주소에서 같은 화면이 보인다.

| 유형 | 관련 과제 | 요구사항 | 선행 |
|---|---|---|---|
| 인프라 | CH-01 | PRD 6.5 C5, API 1.2·1.4, ARCH 1.3·1.4·3·9 (R1·R2·R6·R7) | — |

**설명**: 모노레포(`backend/`, `frontend/`, `simulator/`, `docs/`)가 각각 빌드되고 `docker compose up -d`로 MySQL이 뜨는 상태를 만든다. 이후 모든 작업이 기대는 공통 설정을 이때 넣는다: 주입용 `Clock` 빈 하나, 시각 직렬화 형식, 에러 응답 형식, 관리 포트의 actuator, `spring.jpa.open-in-view=false`, `ddl-auto=validate`.

**착수 전 결정**
- 백엔드 모듈 구조: 결정됨 (사용자 결정, 2026-10-27). ARCH 3.1의 `engine`(순수 Java)·`app` 멀티 모듈로 한다. 레인 엔진을 Spring 없이 쓰라는 PRD 9.7을 모듈 경계로 지킨다 (11장 2번).
- Spring Boot 패치 버전, 앱·관리 포트 번호.
- 프론트 라우터 등 추가 의존성 (새 의존성은 이유를 말하고 허락받는다).

**할 일**
- backend: Gradle(Kotlin DSL), Java 21, Spring Boot 4.x. `Clock.tick(Clock.systemUTC(), Duration.ofMillis(1))` 빈 (R1·R2). `Instant`를 밀리초 3자리 UTC 문자열로 쓰는 Jackson 설정 (R7). JDBC·Hibernate 시간대 UTC (R6). `ApiException(ErrorCode)`와 전역 예외 처리로 API 1.4 형식 `{ "error": { "code", "message", … } }`. 추가 필드 `lane`(레인 상태 거절의 `epoch`, `seq`)과 `fields`(400 필드 에러)를 담을 수 있게 한다 (9장 코드의 enum 뼈대).
- frontend: Vite + React + TypeScript + Tailwind + TanStack Query. Tailwind 디자인 토큰, `components/ui` 기본 컴포넌트(Button, Card, Modal, Toast, Badge, Spinner, EmptyState), Vite 프록시 `/api`·`/ws`.
- 인프라: `docker-compose.yml`(MySQL 8.4), `.env.example`, `.gitignore`(`.env`, `application-local.yml`).
- 문서: `docs/PROGRESS.md`, `docs/adr/` 생성.

**수용 기준**
- [ ] `docker compose up -d` 뒤 `./gradlew bootRun`이 MySQL에 붙어 뜬다.
- [ ] `npm run dev`, `npm run typecheck`, `npm run build`가 통과한다.
- [ ] 없는 경로를 부르면 `404 NOT_FOUND`가 API 1.4 모양으로 온다. 스택 트레이스가 없다.
- [ ] 소수 초가 0인 `Instant`가 `"…T11:00:00.000Z"`로 직렬화된다 (R7).
- [ ] `.env`, `application-local.yml`이 `git status`에 보이지 않는다.

**검증 방법**
- 테스트: 직렬화 형식 테스트, 에러 응답 형식 테스트(`@WebMvcTest`).
- curl: `curl -i $API/api/does-not-exist` → `404`와 `{"error":{"code":"NOT_FOUND",…}}`. `curl $MGMT/actuator/health` → `UP`.
- 화면: `http://localhost:5173`에 빈 레이아웃이 뜬다.

### M1-01 회원가입·로그인·재발급·로그아웃

**착수 전 결정**

- `[GEN]` gen-api.
- `[FE]` P-02 로그인·가입 폼(필드 에러). 앱을 열 때 재발급으로 로그인 복구. 401 처리(재발급 1회 뒤 재시도, 동시에 여러 401이 와도 재발급 1번). Web Locks로 탭 사이 재발급을 하나씩. 로그인 뒤 원래 화면으로 복귀. 공통 헤더(닉네임, 로그아웃, 역할별 메뉴).

- [ ] AC-01-1, AC-01-2 (테스트에서 `Clock`을 15분 넘겨 만료를 재현한다), AC-01-4 (가입 요청의 `role`은 무시되고 언제나 `USER`), AC-01-5.

- [ ] 만료된 Access Token을 붙인 공개 API 요청은 `401`이다. 익명으로 낮춰 받지 않는다.

### M1-02 STOMP 연결 인증

| 유형 | 관련 과제 | 요구사항 | 선행 |
|---|---|---|---|
| 수직 | CH-08 | AC-11-1, AC-11-6, OQ-39, EVENTS 1.2·1.3·1.6, ARCH 8장 | M1-01 |

**설명**: STOMP CONNECT의 `Authorization` 헤더로 사용자를 식별한다. 토큰이 없으면 익명, 만료·위조면 거절, 연결 중 만료는 유지한다. 개인 큐(`/user/queue/notifications`)는 인증된 연결만 구독할 수 있다. 알림 전송은 M3-06에서 붙인다.

**착수 전 결정**: 거절 `ERROR` 프레임의 `message` 값(`TOKEN_EXPIRED`·`TOKEN_INVALID`, ARCH 8.2의 제안)이 EVENTS 1.3과 같은지 확인한다.

**하위 단계** (REST 변경이 없다)
- `[BE]` 인터셉터에서 CONNECT 토큰 검증(REST와 같은 `JwtDecoder`). Principal 이름 = 회원 ID. 인증된 연결의 구독 허용 목록에 `/user/queue/notifications`를 더한다.
- `[FE]` `connectHeaders`에 토큰. 로그인·로그아웃 때 다시 연결. 토큰 만료로 거절되면 재발급 뒤 다시 연결하고, 재발급도 실패하면 토큰 없이 연결한다 (ARCH 8.4).
- `[통합]`

**수용 기준**
- [ ] AC-11-1: 익명 연결은 레인 토픽을 구독할 수 있고 개인 큐는 거부된다.
- [ ] AC-11-6: 만료된 토큰의 CONNECT는 거절, 토큰 없는 CONNECT는 익명, 연결 중 만료(테스트에서 `Clock`을 넘김)는 연결과 개인 큐 구독을 유지한다.
- [ ] 로그아웃하면 STOMP가 토큰 없이 다시 연결된다.

**검증 방법**
- 테스트: STOMP 테스트 클라이언트로 CONNECT 세 경우와 구독 허용·거부.
- 화면: 연결 배지가 로그인 뒤 "인증 연결", 로그아웃 뒤 "익명 연결"로 바뀐다. 개발자 도구의 WebSocket 프레임에서 CONNECT 헤더를 확인한다.

**수용 기준**

### M3 완료 기준 (시연 시나리오)

1. 시드로 레인 4개(레인마다 Lot 3개) 회차를 만들고 시작한다. 패널 4개가 서로 다른 순번으로 독립적으로 진행된다.
2. 레인 2를 남은 7초에 정지한다. 관전 화면이 "정지됨"으로 바뀌고 입찰이 거절된다. 재개하면 남은 시간 10초에서 다시 시작한다.
3. 레인 3의 진행 중 Lot을 강제 종료한다. 유찰로 끝나고 거래가 생기지 않는다.
4. 회차 일괄 정지 → 일괄 재개. 레인마다 저장한 남은 시간으로 다시 시작한다.
5. 입찰에서 밀린 사용자에게 토스트가 뜨고, 알림함에도 남는다.
6. 결제 기한을 2분으로 줄인 설정에서 낙찰자 1은 결제해 거래가 `COMPLETED`, 낙찰자 2는 기한이 지나 `CANCELED`이고 경고 수가 1 늘어난다.
7. 진행 중에 서버를 강제로 재시작한다. 모든 진행 레인이 "정지됨(복구)"이 되고, 관전 화면이 저절로 다시 맞춰지며 현재가와 최고 입찰자가 그대로다. 운영자가 재개하면 남은 시간 10초에서 이어진다.
8. 브라우저를 10초 동안 오프라인으로 두었다가 돌아오면 배너 뒤 4레인이 서버 상태로 돌아온다.
9. 모든 레인이 끝나면 회차가 한 번 끝난다. `audit_log`에 2~4와 7의 재개가 모두 있다.
10. 재계산 스크립트가 이 회차의 DB에서 위반 0건을 보고하고, M3-05의 종합 검증 테스트가 통과한다.
