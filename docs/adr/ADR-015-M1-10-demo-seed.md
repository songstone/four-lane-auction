## 인증과 실행 순서

- ADMIN은 ADR-006의 명시적 `admin-seed`로 별도 준비한다. 이메일·BCrypt 해시를 환경변수로 받으며 기본 앱에서는 프로필을 켜지 않는다. 시드 스크립트에 ADMIN 생성·승격·직접 DB 쓰기를 추가하지 않는다.
- 시드의 계정 비밀번호와 ADMIN 로그인 비밀번호는 환경변수 또는 커밋하지 않는 로컬 파일에서 읽는다. 예시 파일에는 실제 값이 없으며 `.gitignore`가 로컬 설정과 결과물을 제외한다.
- ADMIN 로그인·역할 확인 후 판매자·입찰자를 준비한다. 회원가입의 `409 EMAIL_ALREADY_EXISTS`만 기존 계정으로 처리하고 같은 이메일·비밀번호로 로그인해 `USER` 역할을 확인한다. 다른 오류나 비밀번호 불일치를 성공으로 취급하지 않는다. 기존 계정의 비밀번호·역할은 변경하지 않는다.
- 인증 HTTP 클라이언트는 계정별 Access Token·Refresh 쿠키를 메모리에만 보관한다. 보호 요청의 `401 UNAUTHENTICATED`에서 refresh와 원래 요청 재전송을 한 번만 허용한다. 로그인 실패나 refresh 실패를 반복하지 않는다.
- 판매자 등록 → ADMIN 승인 또는 반려 → 서버 시각 조회 → 회차 생성 → 레인별 전체 편성 → 실제 조회 검증 순서다. 각 레인에 서로 다른 승인 Item을 배정하며 응답에서 받은 ID를 사용한다. 회차를 시작하거나 호가 정책 새 버전을 만들지 않는다.
- 결과에는 실행 설정, 계정 이메일·역할·ID, 생성한 자원 ID, 예정 시각과 확인 결과를 남긴다. 비밀번호·해시·Access Token·Refresh Token·Authorization·Cookie·요청 본문은 로그나 결과 파일에 남기지 않는다.

## 트랜잭션·재시도·시간의 실패 경계

- 시드 전체를 하나의 트랜잭션으로 묶지 않는다. 각 기존 API의 커밋 경계를 유지하며 중간 실패 이전에 완료된 계정·출품물·회차는 남는다. 완료된 자원과 실패 단계를 기록하고 실패 종료한다. 실패를 숨기기 위한 삭제·DB 초기화·직접 보상 SQL은 없다.
- 출품·회차 생성 POST에는 멱등 키 계약이 없다. 네트워크 오류·5xx·응답 유실에 쓰기 요청을 자동 재시도하지 않는다. 서버가 커밋했으나 응답이 유실되면 생성 자원이 결과 파일에 없을 수 있으므로 API·화면으로 확인해야 한다. 새로 실행하면 새 시연 데이터를 만드는 정책이며 동일 실행의 원자적 재개를 보장하지 않는다.
- 편성 PUT은 같은 본문이어도 Lot을 다시 만들어 ID가 바뀐다. 자동 재시도로 멱등성을 가정하지 않는다. API 7.2·ADR-012의 회차·Item 잠금과 중복 편성 금지를 그대로 따른다. 다른 운영자가 같은 회차를 동시에 편집하면 마지막 전체 저장이 남을 수 있다.
- 401에 대한 한 번의 인증 복구는 인증 단계에서 거절된 요청만 대상으로 한다. 커밋 여부가 불확실한 통신 오류·500을 인증 실패로 바꾸지 않는다. Refresh 응답 유실로 토큰이 회전되면 재로그인이 필요할 수 있다.
- `serverTime + X분`은 조회 당시의 서버 시각 기준이다. 조회 후 네트워크 지연이나 서버 시계 점프로 예정 시각이 지나면 기존 API가 거절한다. 생성 후 편성 중 X분이 지나갈 수도 있으며 전체 작업의 완료 시각에서 X분을 보장하지 않는다. OQ-35·OQ-38의 시계 점프·자동 시작 정책은 새로 정하지 않는다.
- M1-08은 예정 회차 조회·사전 구독만 구현된 상태다. 시드 성공은 자동 시작·실제 레인 이벤트·입찰·복구·성능 증거가 아니다.

## 문서 정합성과 검증 범위

- PRD OQ-27을 API 방식으로 닫고 TASKS의 미결 SQL 선택 문구를 정리한다. M1 완료 시연의 내일 20시는 수동 예시로 유지하며 시드는 X분 뒤로 파라미터화한다. 공개·판매자 응답의 최저 낙찰가 비공개와 ADMIN 상세의 기존 OQ-54 예외를 구분한다.
- ARCH 4.4와 PRD OQ-46에 남은 중복 편성 미결 문구는 기존 M1-07 결정으로 맞춘다. 새 중복 정책을 만들지 않는다. CH-11 후보, 부하 규모·봇 행동·k6 구성은 선택하지 않는다.
- 새 Flyway 없음. V1~V7, API·EVENTS 계약, backend·frontend 구현을 유지한다. REST 변경이 없으므로 GEN은 비적용이고 FE 구현도 없다. 순수 스크립트 검사 후 기존 backend clean build(test·testSeoul·verifyTimeSources), frontend lint·typecheck·build를 실행한다.
- 별도 빈 DB·이미지 저장소에 기존 방식으로 ADMIN을 준비한 뒤 시드를 실행하고, 같은 DB에서 이어서 한 번 더 실행한다. 두 실행의 exit 결과와 계정 ID 재사용, 새 출품·회차·편성 ID, N×M Lot·반려 샘플·이미지·공개 응답을 실제 API로 확인한다. 홈 → P-03 미리보기 → Lot 상세와 판매자·운영자 화면을 bootRun + Vite로 확인한다.
- 설정 예시·ignored 로컬 파일·실행 결과의 비밀값 배제를 검사한다. 재시도·부분 실패 테스트와 실제 서버 성공 경로를 구분하고, 실행하지 못한 검증은 NOT_RUN으로 남긴다.

실제 실행 결과·수용 기준별 증거·직접 확인 절차는 PROGRESS M1-10에 기록한다. 이 ADR 자체는 실행 증거가 아니다.
