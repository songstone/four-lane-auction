## 판단과 실행의 경계

- 운영 engine은 java.*와 자기 모듈 코드만 사용한다. Spring·JPA·Jackson·시스템 시계·DB·스레드 실행기·공개 직렬화가 없다. 기존 불변 BidIncrementPolicy를 입력으로 받는다.
- LaneDecision은 다음 경매 상태, 내부 결과, 처리 시각, 영속화할 사실·내부 이벤트·예약 의도를 돌려준다. 실제 저장, 거래·알림 생성, 응답, 발행, 타이머 실행은 M2 이후 어댑터가 맡는다. 생성될 bidId·tradeId·commit 시각·epoch·seq를 엔진이 꾸며 내지 않는다.
- 입력 상태를 바꾸지 않는다. 외부 실행기는 커밋 뒤에만 새 상태를 채택하고 이벤트·예약을 실행해야 한다. 순수 테스트는 DB 원자성이나 커밋 순서 증거가 아니다.
- R13의 계산은 max(이번 Clock 관측값, 직전 처리 시각)이다. 처리 시각은 경매 상태와 별도 메타데이터이며 거절·무시에도 전진할 수 있다. 실제 직전 시각 보관 위치와 락 뒤 Clock 1회 읽기는 M2-01 결정이다.
- Activate(t0)는 회차 시작이 확정한 공통 t0를 사용한다. 전달 지연으로 첫 마감을 처리 시각 기준으로 다시 늘리지 않는다. 후속 Lot은 EndGap/Tick 처리 시각부터 시작한다.
- 내부 이벤트에는 공개 계약 DTO의 역할을 맡기지 않는다. 실제 seq 저장·부여·발행 방식은 M2-01이다. 거절·무시의 상태 이벤트 수는 0이다.

## 시간·거절 규칙의 충돌 해소

- PRD AC-09-3·EVENTS 3.4를 우선한다. 마감 뒤 PlaceBid는 LOT_NOT_BIDDING으로 거절만 하며 Lot·가격·마감·이벤트를 바꾸지 않는다. 마감은 유효한 CheckDeadline 또는 Tick이 수행한다.
- ARCH 5.5.4의 포괄적인 마감 선적용을 이번 명령에 적용하지 않는다. 낡은 타이머의 단계·Lot·세대 검사가 먼저다. 그렇지 않으면 E10을 어긴다. 운영자 정지·강제 종료 경계 B-10은 M3에 남긴다.
- CheckDeadline이 이르면 현재 마감에 같은 세대로 재예약한다. EndGap이 이르면 기존 ARCH대로 무시한다. 유실·조기 간격 타이머의 보완은 Tick이다.
- 마감 확인 세대는 입찰 연장으로 바꾸지 않는다. 새 Lot 시작은 새 확인 세대, 마감 후 새 간격은 새 간격 세대다. 다른 Lot·낡은 세대는 재예약하지 않는다. 중복 마감·간격 명령은 결과를 반복 적용하지 않는다.
- 1초 Tick 안전망·gapEndsAt·R8·R13은 재결정하지 않았다. Tick 주기 자체의 실제 실행·예외 격리·지연 상한 보장은 M2-03이다. 앞으로의 시계 점프 OQ-35도 그대로 미결이다.

## 전이 표 (30칸)

아래 기대값은 구현 전 정한 테스트 원본이다. 타이머의 Lot·세대가 일치하는 정상 입력을 기본으로 하며 불일치·경계는 별도 사례다.

| 단계 | Activate | PlaceBid | CheckDeadline | EndGap | Tick |
|---|---|---|---|---|---|
| READY | 첫 Lot 시작; 빈 편성은 내부 거절(OQ-05) | LANE_NOT_RUNNING | 무시 | 무시 | 무시(OQ-58) |
| BIDDING | 내부 거절(OQ-57) | 조건 5~9 | 이르면 재예약, 기한 도달 시 마감 | 무시 | 기한 도달 시 마감 |
| GAP | 내부 거절(OQ-57) | LOT_NOT_BIDDING | 무시 | 간격 종료 시 다음 Lot/FINISHED | 간격 종료 시 다음 Lot/FINISHED |
| PAUSED_BIDDING | 내부 거절(OQ-57) | LANE_NOT_RUNNING | 무시 | 무시 | 무시 |
| PAUSED_GAP | 내부 거절(OQ-57) | LANE_NOT_RUNNING | 무시 | 무시 | 무시 |
| FINISHED | 내부 거절(OQ-57) | LANE_NOT_RUNNING | 무시 | 무시 | 무시(OQ-58) |

PAUSED 단계는 입력으로만 검증한다. Pause·Resume·ForceClose 명령과 복구 정책은 구현하지 않는다. 유효한 상태의 구성 검증은 제품 전이 규칙을 추가하지 않는다.

## 검증·변경 범위

- AC-10-4 두 순서와 AC-10-5 지연 테스트를 판단 구현보다 먼저 작성한다. 최소 컴파일 골격으로 실제 JUnit 실패를 확인하고 별도 RED 커밋을 남긴다. 실패 로그·XML은 ignored output/m1-09/red에 보존한다. 최종 HEAD는 전부 통과해야 한다.
- FakeClock·FakeScheduler는 엔진 테스트 공용 도구다. Clock만 옮기기, 예약 순서 실행, 실행 지연을 분리한다. 실제 시간 대기나 Thread.sleep으로 업무 시간을 만들지 않는다.
- 테스트용 직렬화 하네스의 동시 제출을 수백 번 반복한다. DB 락·DB 이력 대조·운영 타이머 스트레스와 구별한다.
- engine testSeoul과 실제 테스트 실행 시간 측정을 추가한다. 기존 JUnit 6.0.3의 파라미터화 테스트를 사용하며 새 외부 의존성은 없다.
- Flyway 없음(V1~V7 유지, 다음 번호 V8). GEN·FE·통합·curl·화면 대상 없음. 프론트 회귀 lint·typecheck·build와 전체 backend clean build는 실행한다.
- M2-01: 락·트랜잭션 경계·직전 시각 저장·seq·스냅샷. M2-02: 실제 시작·정책 고정. M2-03/06: DB·타이머·거래·입찰. M2-04/05: 기존 비예정 상세 임시 제한·이벤트. M3: 정지·재개·강제 종료·복구.

실제 실행 시간·수용 기준별 결과·재현 방법은 PROGRESS M1-09에 기록한다. 이 ADR 자체는 실행 증거가 아니다.
