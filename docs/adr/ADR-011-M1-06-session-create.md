## 트랜잭션과 매핑

- 생성은 주입 Clock 1회의 값으로 미래를 판단하고 회차·지정 개수 READY 레인의 created_at·updated_at을 채워 한 트랜잭션으로 저장한다. DB DEFAULT를 사용하지 않는다. 설정 기본값이 범위를 벗어나면 기동 실패한다.
- 회차·레인·Lot의 M0 부분 매핑을 확장하고 @Immutable을 제거한다. 엔티티를 응답으로 직렬화하지 않는다. Lot 편성·경매 전이 API는 후속이다.
- PATCH는 잠금 전 엔티티를 미리 읽지 않는다. 락을 얻은 뒤 Clock을 읽고 예정 시각을 요청한 경우에만 미래를 검사한다. 같은 필드 경합은 직렬 처리 순서의 마지막 값, 다른 필드 경합은 모두 보존된다.
- 조회는 readOnly·JPQL 프로젝션으로 실제 레인·Lot에서 startable·emptyLaneNos를 계산한다. bidPolicyVersion은 저장된 정책 ID로 조회하며 SCHEDULED에서는 null이다.
- V1~V6은 수정하지 않는다. V7은 시간 범위 CHECK만 보강하며 기존 범위 밖 행을 자동 수정하지 않는다. 착수 시 로컬 회차는 0건. 다음 번호는 V8이다.
- 새 의존성·EVENTS 변경 없음. API 0.8에 입력 의미를 먼저 반영한다.

## 실패 경계와 후속

- 모든 수정·후속 시작/편성 경로가 같은 회차 행을 먼저 잠가야 한다. 우회 쓰기·잠금 전 오래된 조회·락 순서 역전은 변경 유실이나 교착을 만들 수 있다. 락 대기는 커넥션을 점유한다.
- 커밋 전 실패는 회차·레인 또는 수정값 전체를 롤백한다. DB 장애·락 타임아웃은 일반 500이다. 생성 커밋 후 응답 유실 뒤 재등록하면 중복 회차가 생길 수 있어 자동 재시도하지 않는다.
- Clock 역행은 updated_at 역행, 앞으로 점프는 미래 입력 거절을 일으킬 수 있다. 검증 직후 +1ms가 지나도 검증 시점에 유효했던 요청은 저장한다. 자동 시작 등록 경계는 M2-02다.
- 홈 보정은 전달 지연만큼 늦을 수 있다. 표본이 없거나 60초 이상 오래되면 남은 시간 표시를 보류한다. 캐시 재사용을 새 표본으로 세지 않는다. 200ms 성능 목표 완료를 주장하지 않는다.
- 예정 시각 변경은 목록의 정렬 키도 바꾼다. ADR-003대로 페이지 사이 고정 스냅샷은 보장하지 않아 페이지를 넘기는 동안 이동한 행을 놓치거나 다시 볼 수 있다. 생성·수정 뒤 목록 재조회로 갱신하며 공개 홈은 30초 재조회를 유지한다.
- 편성 쓰기 M1-07, 자동 시작·시작 경합·정책 고정 M2-02, OQ-35·38은 후속이다. 이번 테스트의 DB 상태 변경은 실제 자동 시작 증거가 아니다.

실제 검증·수용 기준·직접 확인 절차·NOT_RUN은 PROGRESS M1-06에 기록한다.
